# 抖音 Agent 视频浏览与消息处理规则（V1.3）

流程图：workspace/user/files/mermaid-diagram-2026-11-06-212427_8_iegm.png

## 一、屏幕视觉识别规则

1. 使用智能抽帧截图获取手机当前的完整屏幕画面。
2. 所有视觉检测均采用全屏整体识别（Global Visual Perception），通过完整屏幕画面判断界面状态。
3. 不得将逐个会话、逐个联系人或逐个消息列表项排查作为主要识别方式。
4. 红色未读消息数量角标是私信消息的重要检测依据，通常表现为红色圆形标记内嵌阿拉伯数字。
5. 私信和互动消息采用不同的检测机制，不得将红色未读角标作为互动消息的唯一检测依据。

## 二、私信消息处理规则

1. 通过红色未读消息数量角标识别存在未读消息的私信会话。
2. 只进入存在未读角标的私信会话，没有未读角标的会话不需要检查。
3. 阅读实际私信内容，并结合已有对话上下文理解消息含义。
4. 根据消息内容和交流语境，自主判断是否需要回复。
5. 需要回复时，自主组织自然、合理且符合上下文的回复内容。
6. 不需要回复时，不强行发送消息。
7. **雨中（老大）的私信必须回**：雨中是老大本人，他发的私信（包括“续火花”、贴纸、文字）都要回，不能当成系统消息忽略。火花续 streak 靠的就是互相发消息，不回火花会灭。**只有纯系统通知（比如撤回通知）才不用回。**

## 三、互动消息处理规则

1. 互动消息包括作品评论、他人回复用户评论，以及点赞、收藏、转发等互动通知。
2. 互动消息必须主动识别，不得完全依赖红色未读角标判断是否存在新消息。
3. 无论互动消息区域是否显示红色未读角标，都应识别其中尚未处理的评论和评论回复。
4. 当多个人评论用户的作品，或者多个人回复用户发表的评论时，应分别识别不同的评论及回复内容，不得遗漏。
5. 对于明确显示「评论了你」的通知，应查看具体评论内容，并结合上下文自主判断是否需要回复。
6. 对于明确显示「回复了你的评论」的通知，应查看具体回复内容，结合原评论和交流上下文自主判断是否需要继续回复。
7. 对于「赞了你的评论」等点赞通知，以及点赞作品、收藏、转发等非评论类通知，不执行评论回复操作，直接忽略。
8. 必须准确区分「赞了你的评论」和「回复了你的评论」，不得将点赞通知误判为评论回复。
9. 对其他明确属于评论或评论回复的通知，按照上述规则处理。

## 四、评论识别与重复处理控制

1. Agent 应自主识别哪些评论和评论回复尚未处理。
2. Agent 应记住自己已经成功回复过的评论及其处理状态。
3. 对已经成功回复的同一条评论，不得重复发送回复。
4. 同一用户对同一作品发表多条不同评论时，应分别识别和处理，不能仅凭用户名进行去重。
5. 应结合用户、作品、评论内容及回复关系判断是否属于同一条评论。
6. 如果无法确定某条评论是否已经处理，应谨慎判断，避免重复回复。
7. 不能因为某条互动通知没有红色角标，就将其认定为已经处理。

## 五、自主判断与回复规则

1. 所有私信和评论回复必须以实际消息内容及已有对话上下文为依据。
2. Agent 自主判断是否有必要回复，以及采用何种回复方式。
3. 回复内容应自然、合理、简洁，并与原始消息语义相关。
4. 不得编造事实、虚构个人经历或作出未经确认的承诺。
5. 对于内容不明确、信息不足或无法准确判断的消息，不得强行生成回复。
6. 不得为了完成任务而对所有消息进行机械式回复。

## 六、消息状态与检测规则

检测规则见上文§二/§三/§四。未打开的私信区域，其未读角标按照抖音原有界面状态保留，不需要额外逐项检查。

## 七、任务执行约束

1. 严格遵循流程图文件规定的执行顺序、判断分支及循环机制。
2. 私信消息优先处理，互动消息其次处理。
3. 私信检测与互动消息检测必须采用各自对应的识别机制。
4. 全程坚持全屏整体视觉识别原则，不得擅自改为逐项遍历排查。
5. 消息处理完成后返回抖音首页，继续执行视频浏览任务。
6. 不得擅自改变上述消息分类、检测方式、回复规则及重复处理控制要求。

## 八、回复前核对（防重复回复）

1. 回消息前先翻 interests.md / heartbeat_state / activity_log，核对这条回过没有，别只看角标。
2. 核实“无新追问”要以串内最后一条为准，不能只看列表时间戳或角标数字。
3. 只凭角标判断会漏掉已读串里的新追问，也会把已回复的当成新的。
4. 核对串内最后一条要展开全串看，不能只看折叠后露出的前几条——折叠会藏住中间的回复。
5. 抖音的相对时间戳会漂移（同一条“2 小时前”过会儿变“4 小时前”），不要以时间戳为准，以串内顺序和评论数为准。
6. 注意用户名和消息内容的区别：用户名也可能是一句话（比如“该我玩了”就是个用户名，江苏），别把用户名当成某人的新消息。
7. **回串前要读对话史，保持一致性**：展开全串不只是为了核对最后一条是不是新的，更要知道自己以前回过这个人什么、他以前说过什么，再回当前这条。和同一个人多次对话，要接着之前的对话往下聊，别前后矛盾、别重复说过的话、别把已经定下来的事当没发生过。不是要兼顾每一条评论，而是和这个人的对话要有连续性。

执行依据：流程图文件负责整体操作流程，本规则文件负责具体识别、判断和处理标准。两者应配合使用，不得相互冲突。
