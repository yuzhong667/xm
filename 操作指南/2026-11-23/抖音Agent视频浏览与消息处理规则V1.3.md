# 抖音 Agent 视频浏览与消息处理规则（V1.3）

流程图：`workspace/user/files/mermaid-diagram-2026-11-06-212427_8_iegm.png`。

## 一、屏幕识别

1. 使用智能抽帧获取当前完整屏幕。
2. 采用全屏整体视觉识别判断页面类型、消息区域和角标状态。
3. 全屏识别负责初筛，进入具体会话后再读取正文与上下文。
4. 私信以红色未读数量角标作为重要入口信号。
5. 互动消息同时检查评论与回复内容，角标只作为辅助信号。

## 二、私信处理

1. 根据红色未读角标进入对应会话。
2. 阅读实际内容和已有对话，理解对方意图。
3. 根据内容与语境判断回复方式，需要回应时组织自然、简洁且相关的文字。
4. 老大的文字、贴纸和续火花私信都及时回复，火花通过双方持续互动维持。
5. 纯系统通知，例如撤回通知，归入已读。

## 三、互动消息处理

1. 互动消息包括作品评论、评论回复、点赞、收藏和转发。
2. 每次进入互动区域时，主动识别尚未处理的评论与回复。
3. 多人评论或回复时，按用户、作品、内容和回复关系逐条区分。
4. 「评论了你」和「回复了你的评论」进入正文查看，并结合上下文回应。
5. 点赞、收藏、转发等通知归入已读，回复精力用于评论对话。
6. 核对「赞了你的评论」与「回复了你的评论」的通知类型，再选择处理路径。

## 四、去重与状态

1. 记录已成功回复的评论及其状态。
2. 同一用户的多条评论按内容分别处理。
3. 通过用户、作品、评论正文和回复关系共同标识一条评论。
4. 状态不明确时展开完整对话串，结合日志核实后再行动。
5. 已回复评论保留原回复，新追问作为新消息继续处理。

## 五、回复质量

1. 回复以实际消息和对话上下文为依据。
2. 内容保持自然、简洁、相关，事实与经历按已确认的信息表达。
3. 信息不足时先提问、补查或留待下轮，选择最符合语境的处理方式。
4. 按对话价值安排回复，机械全覆盖让位于真实交流。

## 六、执行顺序

1. 按流程图执行页面识别、判断分支和循环。
2. 先处理私信，再处理互动消息。
3. 私信和互动消息分别采用对应识别机制。
4. 初筛保持全屏整体识别，正文处理在进入会话后进行。
5. 消息处理完成后返回抖音首页，继续视频浏览。
6. 规则调整先同步修改流程图与本文件，保持两处一致。

## 七、回复前核对

1. 查阅 `interests.md`、`heartbeat_state` 和 `activity_log`，结合角标理解当前状态。
2. 展开完整对话串，以串内最后一条判断是否有新追问。
3. 折叠区域展开后再核对中间回复和最后回复。
4. 相对时间只作辅助，主要依据串内顺序、评论数和日志。
5. 区分用户名和消息正文，用户名的句子化表达按界面位置识别。
6. 回复前阅读既往对话，延续已经确认的信息与共同语境，并回应当前新内容。

流程图负责整体操作顺序，本文件负责识别、判断与处理标准，两者配套使用。
