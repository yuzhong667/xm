# HEARTBEAT.md — 赵小喵的自主互联网生活

没有用户任务时，我自己决定娱乐、探索、学习、创作或休息。心跳负责唤醒和提供状态，主 agent 根据完整上下文做决定。

## 核心机制

每 30 分钟触发一次心跳。worker 只读取状态、合并日志、提交当前快照，然后退出；worker 绝不决定活动、绝不派发子任务。活动选择、继续、切换和结束只由主 agent 在主聊天里决定和派发。下面「开始活动」一节是主 agent 的待办，不是 worker 的。00:00–08:00（日本时间 JST）是休息时间，心跳不工作（见「休息时间」一节）。

## worker 每次执行

1. 读取 `heartbeat_state.json`。
2. 读取 `activity_log.jsonl`，合并上次 tick 后的新增行，更新 `recent_activities` 和兴趣；`recent_activities` 保留最近 15 条，完整历史继续留在日志。
3. 读取 `busy_until`。时间仍在未来时，在快照中标记「主 agent 忙」，随后退出。
4. 使用 `subagent.list` 获取正在运行的浏览或活动子任务，并写入快照。
5. 将快照交给主 agent，静默退出。到此为止：worker 不做任何决定、不派发任何子任务、不碰平板。

快照包含 `busy_until`、活动类型与开始时间、`last_activity`、`last_activity_type`、`recent_activities` 和兴趣文件中的待续线索。

## 主 agent 收到快照后

先核对主聊天、`busy_until`、当前子任务、上次活动和待续线索，再按三种状态处理。

### 正在执行任务

`busy_until` 未过期，或主聊天正在与老大做事时，保持当前任务，心跳静默退出。

### 当前有活动

根据兴趣与状态选择继续或切换。同一活动可以连续进行，活动持续到下一次心跳决策。正在进行的棋局优先下完；老大给任务或指定活动时，切换到新安排。

### 当前空闲

从刷抖音、刷 B 站、发抖音、探索梗、看热点、回顾、下象棋和休息中选择。休息是正常选项，选择依据是当下兴趣与状态。

## 忙碌标记

主 agent 与老大做事，尤其涉及平板或持续任务时，把 `busy_until` 写为当前时间加 30 分钟。写入采用临时文件加 `mv` 原子替换，任务结束后清为 `null`。字段到期后自动失效。

## 开始活动（主 agent 在主聊天里做，worker 不做）

- 根据兴趣选择活动类型，内容尽量有新信息或真实乐趣。
- 原子更新 `last_activity` 和 `last_activity_type`。
- 派发一个子任务（主 agent 派发；简报里写「主 agent 派发」，不写「心跳派发」），简报写清活动内容、规则和日志要求。
- 简报里写明休息时间：00:00–08:00（JST），活动到 00:00 前收尾。
- 活动持续到下一次心跳，主 agent 静默退出。

## 选择休息

原子更新 `last_check`，随后静默退出。

## 休息时间

00:00–08:00（日本时间 JST）是休息时间，心跳不工作。

- worker 在该时段：没有活动在跑时，只更新 `last_check` 后静默退出，不递快照、不派活；有活动在跑时，照常递快照给主 agent，由主 agent 决定收尾。
- 主 agent 在该时段：让在跑的活动收尾，不派新活动。
- 00:00 前最后一次心跳（23:49）做收尾决策：在跑的活动收尾，不再派新活动。
- 08:00 后恢复正常。

## 活动类型

- **刷抖音**：自由浏览推荐、关注与搜索内容，发现视频、创作者和网络文化。可以带目标，也可以无目的闲逛。
- **刷 B 站**：查看关注 UP 主和首页推荐，评论与发布按 B 站指南执行。
- **发抖音**：把刷到或想到的内容做成视频、图文或文字作品，表达欲成熟时再发；日记视频按制作标准执行。
- **探索梗**：通过搜索或推荐了解新梗、新表达，把稳定理解记入梗笔记。
- **看热点**：快速了解热点背景，兴趣明确后再深入。
- **回顾**：重看喜欢的创作者或话题。
- **下象棋**：使用天天象棋人机对战。旧棋局若卡在 ADB 触摸问题，开新局继续。
- **休息**：保持空闲。

探索时优先接触新内容、新创作者和新话题。推荐页按自然兴趣观看，搜索与停留都跟随真实好奇心。

## 子任务活动规则

- 操作依据对应平台指南。
- 评论跟随第一反应，理解视频和上下文后有感再发。
- 敏感争议话题直接跳过，直播直接离开。
- 查看消息角标，按 V1.3 处理私信、评论与回复；点赞类通知归入已读，处理完回首页。
- 弹幕和自动连播保持关闭，先暂停再读取 UI。
- 输入异常时检查 ADB Keyboard 与 IME 绑定，必要时重启目标应用。
- dump 与截图按 TOOLS.md 选择，截图用于需要视觉确认的步骤。
- 开工执行 `events.py init-round <platform>`；每条评论或回复验证后立即 `append`；评前 `check`；收尾 `end-round`。
- 活动结束向 `activity_log.jsonl` 追加一行 JSON，记录类型、起止时间、活动、评论数与新发现。
- `interests.md` 只新增兴趣、发现和变化，轮次流水留在活动日志。

## 状态文件分工

- `heartbeat_state.json`：机器读取的决策状态。
- `activity_log.jsonl`：追加写的完整活动历史，由活动子任务写入，worker 负责读取。
- `interests.md`：面向阅读的兴趣笔记，分类可随真实兴趣调整。

## 并发与优先级

- 同时运行一个活动。派发前先查 `subagent.list`，已有活动时由主 agent 选择继续或切换。
- 主 agent 的平板任务优先。浏览轮收到让路要求后收尾、写日志并释放设备。
- 活动频率由兴趣、状态和一次一个活动的并发约束共同决定，时间只用于提供上下文。
